{{- $scheme := include "tsagent.httpScheme" . | lower -}}
tsagent {{ .Chart.AppVersion }} is installed as {{ $fullname }} in {{ $ns }}.
{{- if .Values.build.enabled }}

0. Build the image in-cluster (a ConfigChange trigger usually starts the first build for you):

     oc start-build {{ $fullname }} -n {{ $ns }} --follow
{{- if .Values.build.autoDeploy }}
   The Deployment rolls automatically whenever a build pushes {{ include "tsagent.imageStreamName" . }}:{{ .Values.build.outputTag }}.
{{- end }}
{{- end }}

1. Check it came up:

     oc rollout status deploy/{{ $fullname }} -n {{ $ns }}
     oc logs -f deploy/{{ $fullname }} -n {{ $ns }}

2. Point AlertManager at it. Inside the cluster the webhook URL is:

     {{ $scheme }}://{{ $fullname }}.{{ $ns }}.svc:{{ .Values.service.port }}/alerts

     receivers:
       - name: tsagent
         webhook_configs:
           - url: {{ $scheme }}://{{ $fullname }}.{{ $ns }}.svc:{{ .Values.service.port }}/alerts
             send_resolved: true
{{- if .Values.tls.serviceServingCert.enabled }}
             http_config:
               tls_config:
                 ca_file: /var/run/secrets/kubernetes.io/serviceaccount/service-ca.crt
{{- end }}
{{- if .Values.route.enabled }}

3. Dashboard and API through the Route:

     HOST=$(oc get route {{ $fullname }} -n {{ $ns }} -o jsonpath='{.spec.host}')
     echo https://$HOST/              # dashboard
     curl https://$HOST/incidents
     curl "https://$HOST/incidents/<id>/report?format=md"
{{- end }}

4. Fire a synthetic alarm to prove the path end to end:

     oc exec deploy/{{ $fullname }} -n {{ $ns }} -- python -c "import json,urllib.request,ssl; \
       urllib.request.urlopen(urllib.request.Request('{{ $scheme }}://localhost:{{ .Values.containerPort }}/alerts', \
       data=json.dumps({'version':'4','status':'firing','alerts':[{'status':'firing', \
       'labels':{'alertname':'NodeDown','severity':'critical','instance':'overcloud-compute-0:9100'}, \
       'annotations':{'summary':'synthetic test'},'startsAt':'2026-01-01T00:00:00Z'}]}).encode(), \
       headers={'Content-Type':'application/json'}), context=ssl._create_unverified_context()).read()"

   Then force correlation instead of waiting {{ dig "correlation" "window_seconds" 300 $settings }}s:

     oc exec deploy/{{ $fullname }} -n {{ $ns }} -- python -c "import urllib.request,ssl; \
       urllib.request.urlopen(urllib.request.Request('{{ $scheme }}://localhost:{{ .Values.containerPort }}/correlation/flush', \
       method='POST'), context=ssl._create_unverified_context()).read()"

5. Change config without rebuilding: edit your values and `helm upgrade` (the pod restarts on
   config change), or nudge a single setting live:

     oc set env deploy/{{ $fullname }} -n {{ $ns }} TSAGENT_CORRELATION__WINDOW_SECONDS=60

   `helm test {{ .Release.Name }} -n {{ $ns }}` checks /readyz through the Service.

{{- if not .Values.secrets.sshPrivateKey }}

NOTE: no SSH private key was given to the chart. Unless the directors use password auth
(secrets.env.TSAGENT_DIRECTOR_PASSWORD), the Node Agent cannot reach any director and incidents are
investigated from metrics alone. Prefer secrets.existingSecret over keys in a values file.
{{- end }}
{{- end }}
